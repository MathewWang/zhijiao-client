# 生成式互动（0.4.0）

发送端制作完整效果，接收端同意即播。两台电脑均升级到 0.4.0 或更新，并确认“云端在线”、已互为好友。服务端需要支持 interactionProtocol:2。旧版客户端不能接收新版效果，发送页面会提示升级；已有 version:1 邀请保留原来的接收端创作流程。

## 双机验证

1. A 在聊天输入框点击 + → 送花或烟花，头像选 B，填写留言，可展开创作要求。
2. 勾选本次模型授权，点击“制作效果”。A 的本地 Agent 输出完整自包含 HTML/CSS/JS，尚未发送给 B。
3. 点击“预览效果”，本机隔离播放器展示。运行报错会阻止发送，需重新制作；美术效果由主人确认。关闭预览后点击“发送效果”。
4. B 从聊天“查看互动”或人物旁“有心意待接收”打开记录。点击“同意并播放”直接进入展示，不再等待模型编写，也不需要再点一次播放。正常播放不调用 B 的模型。
5. B 可选勾选“运行报错时允许本机 Agent 尝试修复一次”。仅在脚本运行报错时调用模型修复收到的代码，成功后自动重新播放一次。未预先授权时，显示错误，由 B 再勾选授权并点击“修复后播放”。修复失败不会循环重试。
6. 20 秒后自动结束，也可回复并“收下并结束”。A 收到展示结果与回复。

## 协议与持久化

version:2 的邀请同时携带 intent、presentation 和 artifact（完整 HTML 源码与 SHA-256）。单个源码不超过 60KB，服务器重新校验并保存，只有双方可读取。公开人物立绘由两端本地素材提供，不把聊天记录、文件和凭证交给效果。接收端修复后的源码留在接收端本机。

- 仅可向支持 protocol:2 的好友发送新版效果；服务端保留 protocol:1 的兼容处理。
- B 离线时邀请保存在云端，恢复在线后同步；未经同意不播放、不调用模型。
- 同意在服务端原子地从 pending 转为 playing；已有其他播放时拒绝，避免两个效果同时开始。
- 发送使用幂等 key，同意重试不会重复创建或调用模型。播放、错误和结束回执有明确状态与批次。
- 播放出错变为 failed；修复是显式授权的一次新批次：accepted → ready → playing。最多修复一次，仍失败时请发送方重新制作。
- 本地保存播放文件、错误和待投递回执。断网不会触发重新 coding；重启中断的创作/修复标为失败，不自动重跑模型。
- 离开播放页不会自动重播。未确认结束的展示可以返回记录继续查看或结束；已结束、拒绝、撤回或过期的效果不可再播放。
- 当前发送端制作结果保存在页面内存，制作后请先预览并发送，关闭页面或切换页面可能需要重新制作。

## 架构与隔离

shared/interactions.mjs 定义两个版本的协议和状态机。runtime/interaction-runtime.mjs 负责发送端制作、接收端导入播放、一次修复和持久化回执。src/Interactions.tsx 负责统一玩法表单、预览和播放器。新增玩法复用 PlayComposer 与同一传输/播放器，不另建收发链路。

Agent 通过现有非交互 CLI 返回源码文本，不获得额外文件、Shell 或系统权限。代码运行于 sandbox="allow-scripts" 的 opaque-origin iframe；宿主 CSP 禁止联网、子框架、表单等。Electron 继续禁止外部网络、下载、弹窗及导航。只向作品提供本次留言与公开人物立绘 data URL。运行报错和待修复代码均作为不可信素材传给模型。

单次展示 5–60 秒（内置主题默认 20 秒），无声音。模型美术质量需发送方预览确认；自动检测覆盖脚本错误与未处理的 Promise 拒绝，不保证识别所有空白或视觉问题。串门保留原协议，界面与生成式玩法共用头像选人、留言、附加选项、底部主按钮；往来记录统一放在右上角。
