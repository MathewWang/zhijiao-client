# 生成式互动（0.3.0）

双机均升级到 main（0.3.0 或更新），保留原 .data 与云端身份，准备好已安装、已登录的本地模型 CLI。无需重新注册或重新加好友。服务端也必须升级到支持 /v1/interactions 的版本。升级后设备同步会宣告 interactionProtocol:1；好友未宣告时发送选项提示需要升级。

## 双机验证

1. 两台电脑启动客户端并确认“云端在线”；确保已互为好友。
2. A 在聊天输入框点击 + → 送花，选择 B，写祝福语，可展开创作要求。
3. 勾选本次生成授权，点击“生成方案”。此时 A 的本机 Agent 调用一次模型生成结构化方案，没有向 B 发送。
4. 检查方案，点击“发送互动邀请”。B 的聊天出现互动通知。
5. B 点击“查看互动”，检查方案；勾选创作授权后点击“接收并创作”。此时 B 的本地 Agent 调用模型，编写自包含 HTML/CSS/JS。拒绝不会调用模型。
6. 创作成功，B 点击“播放效果”。可看到内置人物素材与祝福文字（具体美术由本地模型生成）。20 秒后自动结束，也可输入回复，点击“收下并结束”。A 会收到展示结束和回复汇报。
7. A 改选烟花重复测试。两种玩法使用同一协议、创作执行器、隔离播放器、回执与失败恢复逻辑。

## 边界验证

- B 离线时 A 可向已宣告能力的好友发送，B 恢复运行后同步邀请；接受前不会创作。
- 重复点击发送使用同一 key，不产生多条邀请。发送失败后不要修改方案即可重试。
- A 可撤回未播放的互动；已拒绝、撤回、过期的邀请不可开始展示。
- 模型失败不会自动重试或自动消耗额度，需 B 再次勾选授权重试。
- 创作中退出客户端，重启后将中断标记为失败并同步；不自动重跑模型。
- 展示文件只保存在 B 本机，云端只保存方案与状态。播放中退出/离开页面不会自动重播；可回到互动页面结束未确认的展示。
- 收下结果先写本地再同步云端，断网时等待同步，不重新创作。

## 架构

shared/interactions.mjs 定义版本化协议及状态机。runtime/interaction-runtime.mjs 负责方案生成、本地创作与持久化回执。src/Interactions.tsx 是统一玩法界面与播放器。新增主题只需增加玩法定义，不需要单独的收发 API。

Agent 通过现有非交互 CLI 返回代码文本，不获得额外文件、Shell 或系统权限。生成 HTML 运行于 sandbox="allow-scripts" 的 opaque-origin iframe，无 same-origin、弹窗、表单等权限；宿主强制 CSP 禁止联网和子框架；Electron 同时禁止外部网络、下载、弹出窗口及页面导航。仅向生成效果提供本次祝福语与公开人物立绘 data URL，不提供私人聊天、文件或凭证。网页预览可用于查看界面；正式互动效果请在桌面客户端运行。

## 当前限制

这是第一版：单次效果 5–60 秒（内置主题默认 20 秒）、不播放声音；不保证每个模型生成的美术和动作质量一致。不会在朋友未确认时自动 coding；暂无直接用聊天自然语言触发送花，入口位于 + 玩法面板。旧串门保留原协议，避免影响已部署客户端。

0.3.1 起，串门和生成式互动共用 PlayComposer 发送组件：头像选择好友、留言、可展开的附加项、右侧主操作与说明。玩法记录统一从右上角“往来记录”进入；聊天中的“查看互动”直接打开记录。新玩法应复用该组件，不另起一套发送表单。
