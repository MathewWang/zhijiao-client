# 桌面客户端升级（0.4.0）

新版把送花、烟花改为发送端制作完整效果，预览后发送；接收方点「同意并播放」直接展示。正常播放不调用模型，可选授权运行报错后修复一次。双方均需升级到 0.4.0 或更新版本。官方云端已支持新协议；自建 Relay 必须支持 interactionProtocol:2。

## 交给另一台电脑的 Codex

> 帮我升级现有知交信使客户端到 0.4.0 或更新版本：https://github.com/MathewWang/zhijiao-client 。先读 AGENTS.md、INSTALL.md 和 docs/upgrade.md。复用原项目，保留 .data、角色、聊天、好友、云端设备身份和配置，不要重新注册。先确认没有正在进行的任务或互动，正常退出客户端和独立后台，将 .data 备份到项目外的私有目录。检查 Git 分支和本地改动；干净 main 分支运行 npm run desktop:update，再 npm run desktop。若有定制改动或分支分叉，保留并说明，不覆盖、不 reset、不 clean。启动后确认版本、原身份和云端连接。不要自动切换 CLI、调用模型或向真实好友发测试消息。

## 手动更新

先结束任务或互动，退出桌面与独立运行的后台，备份整个 `.data`。在原项目目录执行：

```sh
npm run desktop:update
npm run desktop
```

`desktop:update` 只更新干净的 main，使用 `git pull --ff-only origin main`，安装依赖并构建。存在本地修改、未跟踪文件或分支分叉时会停止，不自动合并或覆盖。更新后不会自己启动客户端。不要重新克隆覆盖旧目录，也不要复制另一台电脑的 config.json。

Electron 下载慢时可为更新命令指定镜像：

```sh
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm run desktop:update
```

只刷新页面不能升级后台；必须完整退出并重新启动。不要同时运行桌面与独立无头 Client。

## 升级后检查

- 设置里显示 0.4.0 或更新版本，原角色、好友、聊天记录保留，状态为“云端在线”。
- 聊天输入框「+」提供串门、送花和烟花，顶部只保留聊天 / 好友入口；玩法往来记录在右上角。
- 好友仍展示公开资料与在线状态。主人聊天与助理汇报显示在聊天中；好友问题继续由主人确认后回复。
- 送花 / 烟花先在发送方“制作效果”和“预览效果”，确认后“发送效果”；接收方“同意并播放”立即展示。
- 对方还未升级时，发送页提示“需升级客户端”。已有旧版方案邀请保留接收端创作的旧流程，不会自动转换为新效果。

具体双机测试见 [互动指南](INTERACTIONS.md)，安装环境见 [INSTALL.md](../INSTALL.md)。源码升级保留数据，但不能代替 `.data` 备份。

## 更新提醒

设置中可点“检查更新”，新版提醒会进入自己的 Agent 聊天，带“复制升级指引”按钮。启动约 10 秒后检查，此后每 30 分钟检查，同一版本只提醒一次；不会自动安装。尚未提供此功能的旧客户端先手动升级一次。
